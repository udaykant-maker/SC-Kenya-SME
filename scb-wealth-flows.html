● Flow 01

Customer Onboarding

SME admin fetches customer from SCB core, enriches for Sanlam requirements, and creates the customer record in both Vault22 and Sanlam in a single transaction.

Validation Rules
  • RelId must exist in SCB CIF and return a 200 response.
  • KYC tier must be ≥ Tier 2 for investment eligibility.
  • At least one active CASA account required.
  • Enrichment fields mandatory before submission to Sanlam.
System Calls
  • GET /scb/cif/{relId}
  • GET /scb/accounts?relId=
  • POST /v1/customers (Vault22)
  • POST /sanlam/investors
Failure Handling
  • RelId not found → wizard blocks at step 2, clear error shown.
  • KYC below tier → surfaces required action to admin.
  • Sanlam API error → Vault22 record rolled back, retry offered.
  • Duplicate detected → admin redirected to existing profile.

⚠ Buy Order — Failure Paths
Debit fails — Order cancelled at gate; recurring subscription queued for retry next business day.
Payment confirmed after 07:00 — Order rolls into next day's batch automatically.
Sanlam API timeout at submit — Alert raised (L4 Sanlam Integration); Ops retries from order detail.
Sanlam misses 14:00 — Order marked Failed; funds held in collection; escalation to L4.

⚠ Sell Order — Failure Paths
Insufficient units — Order rejected at validation; clear error shown to admin.
Sanlam API failure at submit — Alert raised; manual investigation by Ops; retry or escalate.
Customer bank credit fails — Amount parked in suspense; surfaced on Credit Failure Report; Ops resolves.
Amount mismatch on settlement — Three-party alert (SCB + Vault22 + Sanlam); distribution blocked until resolved.
